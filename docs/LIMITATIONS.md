# BiofilmAI — Limitations

## 1. No Trained Model Weights

The PyTorch model architecture is complete and compiles without errors. However, **no trained model weights exist**. The model has never been trained on any dataset. All predictions generated by the system are produced by a heuristic demo engine, not by the neural network.

## 2. No Real Multimodal Labelled Dataset

**No publicly available dataset provides all four required modalities (microscopy, spectroscopy, genomics, clinical metadata) for the same biofilm samples with consistent labels.** We investigated eight candidate datasets and repositories. Every candidate was missing at least two to three modalities. The dataset loader and validator are built and ready, but they have never loaded real data.

## 3. Demo Predictions Are Not Scientific Predictions

The demo inference engine uses a simple heuristic (modality count + random noise) to generate probabilities. These probabilities are:
- **Not based on any biological data**
- **Not reproducible** (they include random noise)
- **Not scientifically meaningful**
- **Clearly labeled as DEMO MODE in every response**

No one should interpret demo outputs as biofilm research findings.

## 4. No Clinical Validation

The system has not been clinically validated. It has never been tested on patient samples, clinical wound swabs, or any real biological specimens. There is:
- No IRB approval
- No clinical trial registration
- No comparison against gold-standard laboratory methods
- No peer-reviewed publication of results

## 5. No Clinical Deployment

BiofilmAI is a research prototype intended for educational and demonstration purposes. It is **not**:
- A medical device
- A diagnostic system
- Cleared or approved by any regulatory authority (FDA, CE, CDSCO, etc.)
- Suitable for making decisions about patient care

## 6. Public Datasets Cannot Be Merged

It may be tempting to combine separate single-modality datasets (e.g., DeepBacs images + Ho et al. Raman spectra + NCBI 16S sequences) into a single training set. This is scientifically invalid because:
- Different samples — there is no sample-level correspondence across datasets
- Different organisms — datasets use different bacterial species and strains
- Different biological contexts — one dataset uses laboratory cultures, another uses environmental samples
- Different labeling schemes — growth stages, species names, and environmental conditions cannot be reconciled

Training a cross-attention fusion model requires **paired multimodal data from the same samples**, which does not currently exist in any public repository.

## 7. Future Data Collection Requirements

To train the real model, a researcher would need to collect:
- 50–100+ samples with all four modalities
- A consistent binary biofilm label for each sample
- Identical sample identifiers across all modalities
- De-identified clinical metadata

This is feasible in a laboratory setting but has not been done as part of this project.

## 8. Additional Technical Limitations

| Limitation | Detail |
|---|---|
| **Storage** | Analysis history is stored in memory. All data is lost when the backend restarts. |
| **Authentication** | No user authentication is implemented. |
| **File persistence** | Uploaded files are validated but not stored to disk. |
| **Preprocessing** | Preprocessing pipelines have not been validated against real data. |
| **Attention conversion** | Real attention weights from the model are not yet converted into the API's CrossAttentionMap format. |
| **Modality contribution** | Contribution scores in demo mode are random. Real scores require trained model attention. |
